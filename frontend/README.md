# SIM Training — React frontend

React + Vite + Yarn. Отдельный фронт для Django API, без изменения печатных шаблонов тренировок.

## Запуск локально

Бэкенд запускается из корня `pilot_logbook` в PyCharm либо командой:

```sh
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Фронт удобно открыть отдельной папкой в VS Code:

```sh
cd /Users/vadimgushchin/Desktop/Djangoprojects/pilot_logbook/frontend
yarn install --frozen-lockfile
yarn dev
```

Адрес: http://127.0.0.1:5174/. Зависимости уже установлены; повторный `yarn install` нужен после получения проекта на другом компьютере или изменения lockfile. Используется Node 22.18.0, Yarn 1.22.22.

Vite проксирует `/api`, `/static`, `/pilot-partial` и `/admin` в Django на `127.0.0.1:8000`. Для другого адреса создайте `.env.local` по примеру `.env.example` и перезапустите Vite. Пароли БД и Django SECRET_KEY во фронт не копировать.

```sh
yarn build
yarn format
```

Сборка находится в `dist/`. Node-зависимости, сборка и `.env.local` исключены из Git. Шрифты включены в сборку и не требуют обращения к Google Fonts.

## Что подключено

- Вход по существующей учётной записи Django с определением ролей из связанных профилей. Совмещённые роли переключаются в верхнем меню.
- Личный календарь; даже технический суперпользователь не получает все чужие назначения в личном календаре. У инструктора связанные записи экипажа показаны одним занятием.
- Предварительный просмотр программы будущих тренировок для слушателя и инструктора.
- React-страница экипажа: отдельные оценки, замечания, таймеры и локальные черновики двух пилотов; явное связывание старых записей.
- История предыдущих инструкторов по назначенным пилотам с датой, автором, общими замечаниями и деталями упражнений. Доступ только для чтения.
- Просмотр своих итоговых результатов слушателем. Печать выполненного задания через защищённый API по существующим Django-шаблонам.
- Сводная аналитика: распределение оценок, средние по компетенциям EBT. «Не оценивалось» исключается из среднего.
- Даты и время во фронте отображаются в UTC. Исходные даты в БД не изменяются.

## Границы первой версии

Ознакомление в веб-кабинете и версии результатов подключены. Полноценный офлайн-режим отдельного приложения iPad — следующий этап. Веб-черновики сохраняются в браузере и не переносятся на другое устройство. Для загрузки расписания и заданий требуется сервер.

Фронт использует существующий TokenAuthentication: токен браузерной вкладки хранится в sessionStorage, черновики — отдельно по пользователю и назначению в localStorage. Выход удаляет токен из текущей вкладки, но не отзывает его на остальных устройствах. Не передавать пароли или токены через URL. Для рабочего выпуска потребуется отдельный этап настройки безопасного веб-входа, окружения и публикации.

Ответственный с правом `pilot_training.revise_result` может создавать исправленную версию результата с обязательной причиной. Суперпользователь также имеет это право. Слушатель подтверждает точную версию кнопкой «Ознакомлен» на странице результатов; исправление требует нового ознакомления. Прежние версии и подтверждения сохраняются, историческую версию можно распечатать. Повторная отправка подтверждения не создаёт дубль. Серверное время события хранится отдельно от переданного устройством времени. Это техническая фиксация ознакомления; документы и правила применения ПЭП согласовываются отдельно.

Новые формы составления расписания и управления пользователями ещё не перенесены из Django. Старая версия Django-фронта сохранена.
